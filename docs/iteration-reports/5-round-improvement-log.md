## Round 1：美术可信度

竞品优势：

- 肥鹅美食街、我的花园世界都用明确题材美术建立第一眼吸引力。
- 图标和场景承载玩法理解，玩家不需要靠文字猜物品。

原型不足：

- 棋盘、订单、生成器用单字占位，显得临时且不可试玩。
- 小店场景是 CSS 简图，情绪价值弱。

本轮改进：

- 生成 AI 小店风格基准图：`src/assets/generated/style-reference-shop.png`。
- 接入运行时压缩图：`src/assets/generated/style-reference-shop-runtime.jpg`。
- 新增 SVG 常用素材模块：`src/ui/art.ts`。
- 棋盘、订单、生成器、制作台、顾客头像全部替换为具体图形。

验证：

- `npm run build` 通过。
- Chrome 首屏可见小店插画和物品图标。

## Round 2：非强制新手教程

竞品优势：

- 成熟合成经营产品会先让玩家完成一个短闭环，再逐步展开复杂系统。
- 梦幻消除战、开间小店这类经营产品都会用剧情或任务牵引第一步。

原型不足：

- 初始页面同时出现棋盘、订单、配方、制作台、装修，新玩家不知道先点哪里。

本轮改进：

- 新增非强制教程状态：`tutorial`。
- 新增教程操作：打开、关闭、上一步、下一步。
- 教程不阻塞操作，可随时用右上角 `?` 重新打开。
- 当前教程步骤会高亮相关模块。

验证：

- Chrome 首屏显示 `新手提示 1/6`。
- 教程卡不遮挡棋盘和订单。

## Round 3：第一目标聚焦

竞品优势：

- 肥鹅美食街开局围绕交付订单建立目标感。
- 我的花园世界用订单和花艺目标减少玩家迷路。

原型不足：

- 订单太多，玩家不知道哪一个是主线。
- 缺少“下一步该做什么”的即时目标。

本轮改进：

- 新增当前推荐目标卡：`第一目标：完成街坊早餐`。
- 推荐目标直接展示缺少物品和拥有数量。
- 完成早餐后切换到第二目标：做出青菜包。

验证：

- Chrome 首屏可见 `当前推荐目标`。
- 推荐目标与订单 `order_001` 状态同步。

## Round 4：缺材料反馈

竞品优势：

- 合成经营游戏会让玩家知道订单差什么，减少无效点击。
- 菜谱/订单的可完成状态越清楚，越容易形成短循环。

原型不足：

- 只有 `0/1` 数量，不够明确。
- 配方无法开始时不知道是材料不足还是制作台忙。

本轮改进：

- 新增 `missingSummary()`。
- 订单卡显示 `还差 ...` 或 `材料齐了，可以提交`。
- 配方卡显示 `还差 ...`、`材料齐了，可以开做` 或 `制作台正忙`。
- 推荐订单增加视觉标记。

验证：

- Chrome 首屏可见推荐订单与缺材料提示。
- `npm run build` 通过。

## Round 5：首屏性能与资源策略

竞品优势：

- 微信小游戏首屏加载必须克制，尤其是大图和动效资源。
- 经营类小游戏需要在“情绪画面”和“包体/加载速度”之间平衡。

原型不足：

- 原 AI PNG 基准图 2.5MB，直接进入首屏过重。

本轮改进：

- 保留源图作为风格基准。
- 生成运行时 JPG 压缩图，从 2.5MB 降到约 221KB。
- UI 改为引用 `style-reference-shop-runtime.jpg`。
- 记录美术资产策略到 `docs/art-asset-manifest.md`。

验证：

- 压缩文件存在且体积约 221KB。
- `npm run build` 通过。

## 仍然落后竞品的地方

- 没有正式 PNG 图标包，SVG 只能支撑 MVP。
- 顾客故事还没有弹窗演出和奖励仪式感。
- 店铺装修仍是阶段展示，不是自由摆放。
- 没有好友互访、社交赠送、图鉴收集。
- 没有真实微信小游戏的广告、分享、云存档链路。

## 下一轮建议

1. 加顾客故事弹窗和顾客好感度。
2. 用 AI 生成 24 个正式 PNG 物品图标。
3. 做首日任务线：完成早餐、制作青菜包、修门头。
4. 接入微信小游戏项目结构或 Cocos 工程。
