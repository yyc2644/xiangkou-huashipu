# 后续完善记录：首日任务与故事演出

## 本轮目标

继续把 Web MVP 从“系统都摆出来”推进到“玩家知道下一步，并且完成订单有情绪反馈”。

## 新增内容

### 1. 今日开张任务线

新增左侧任务面板，覆盖首日关键路径：

1. 取一次材料。
2. 合成小青菜。
3. 完成街坊早餐。
4. 开始制作青菜包。
5. 完成热腾腾包子。
6. 修一次门头。

任务完成状态由玩法状态派生，同时记录 `milestones` 兼容后续埋点和云存档。

涉及文件：

- `src/game/types.ts`
- `src/game/state.ts`
- `src/ui/render.ts`
- `src/styles.css`

### 2. 顾客故事弹窗

故事订单完成后，弹出顾客剧情卡：

- 展示顾客头像。
- 展示订单标题。
- 展示当前顾客章节文案。
- 展示已获得奖励。

这一步补足“交订单只是数字变化”的问题，让故事订单更接近《梦幻消除战》和《开间小店》的情绪反馈。

### 3. 渐进展开

首屏复杂度继续降低：

- 早餐完成前，“菜品与礼盒”默认收起。
- 第一个故事订单完成前，“店铺升级”默认收起。
- 保留模块入口，不强制阻断老玩家操作。

这样比直接隐藏系统更稳：新手不被信息量压住，测试人员也能快速展开检查。

## 当前验证

- `npm run build` 通过。
- Chrome 页面可见“今日开张”任务面板。
- 旧存档兼容：任务状态会从已有订单、生成器充能和店铺等级推导。

## 下一步建议

1. 给任务增加可领取的小额奖励，而不是只显示目标收益。
2. 加入订单完成动效和金币飞行动效。
3. 把故事弹窗扩展成 2-3 句对白，而不是单句文案。
4. 将 Day 1 任务线写入真实配置，方便运营调整。
