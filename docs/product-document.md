## 1. 产品概述

《巷口花食铺》是一款面向微信小游戏方向的治愈系合成经营游戏。玩家经营一间重新开张的老街小店，通过取材、棋盘二合、制作菜品和礼盒、完成顾客订单、修复店铺区域，逐步解锁街坊故事。

当前阶段不是正式微信小游戏包，而是用于验证玩法闭环、首局引导、移动端布局和内容节奏的 Web MVP。后续可迁移到 Cocos Creator 或微信小游戏工程。

### 一句话定位

老街治愈小店 + 花食题材 + 合成棋盘 + 订单经营 + 轻故事装修。

### 产品关键词

- 治愈、温暖、明亮。
- 微信小游戏、竖屏、一屏操作。
- 合成经营、订单目标、店铺修复。
- 花材、食材、手作礼盒、街坊故事。

## 2. 目标用户

### 核心用户

- 喜欢合成、收集、经营、装修的休闲玩家。
- 偏好轻剧情和治愈美术的女性向用户。
- 微信小游戏碎片化使用场景用户。

### 使用场景

- 通勤、午休、睡前 3-8 分钟短局。
- 每日任务驱动回访。
- 看广告补体力或加速制作。
- 完成订单后获得小剧情和店铺变化反馈。

## 3. 竞品参考边界

参考品类结构和用户爽点，不复制任何名称、角色、美术、数值、文案或 UI。

### 参考方向

- 《肥鹅美食街》：合成食材、订单、经营主题。
- 《梦幻消除战》：合成经营、剧情与装修牵引。
- 《开间小店》：小店经营、顾客和成长目标。
- 《抓大鹅》：微信小游戏轻量传播和即时可玩。
- 《我的花园世界》：花材、订单、庭院/花坊情绪价值。

### 本项目差异点

- 食材和花材混合，避免单纯餐厅或花店。
- 现代老街小店，不做强古风。
- 首屏主操作集中在棋盘和取材，任务、订单、图谱、店铺放入底部入口。
- MVP 优先验证“能不能顺着第一分钟玩下去”。

## 4. 产品目标

### MVP 目标

验证以下问题：

1. 玩家是否能在手机竖屏内理解第一步该做什么。
2. 玩家是否能完成取材、合成、订单提交的短循环。
3. 合成图谱是否能解释缺材料怎么来。
4. 店铺修复和顾客故事是否能形成下一阶段目标。
5. 当前 Web 原型是否能稳定迁移到小游戏工程。

### 需求闭环目标

每个核心系统必须回答一个明确的玩家问题：

- 新手教程：我第一步该做什么。
- 棋盘：我怎么把低级材料变成目标材料。
- 订单：我现在为什么要合成这些东西。
- 图谱：我缺的材料从哪里来。
- 制作台：基础材料如何转化成更高价值目标。
- 今日任务：我下一步优先做什么。
- 店铺升级：订单收益沉淀到哪里。
- 顾客故事：为什么这个小店值得继续经营。

需求闭环和数值校准详见 `docs/requirements-and-balance.md`。

### MVP 不做

- 不接真实微信登录。
- 不接真实广告、支付和分享。
- 不做后端账号体系。
- 不做自由摆放装修。
- 不做完整 Cocos 工程。
- 不做真实商业化数值。

## 5. 核心循环

```text
体力
-> 点击生成器取材
-> 棋盘二合升级
-> 制作台加工菜品或礼盒
-> 提交顾客订单
-> 获得金币、经验、故事点
-> 升级店铺区域
-> 解锁更多订单和顾客故事
```

### 短循环

取材 -> 合成 -> 提交普通订单 -> 获得金币和经验。

### 中循环

取材 -> 合成高级材料 -> 制作菜品或礼盒 -> 提交故事订单 -> 获得故事点。

### 长循环

完成订单 -> 修复店铺 -> 解锁故事和更高阶目标 -> 形成每日回访。

## 7. 新手教程设计

### 设计原则

- 教程不是说明图，必须能操作。
- 每一步只教一个动作。
- 未完成当前动作时，“下一步”不可点击。
- 教程内容必须和真实首单一致。
- 4 步内完成，不拉长首局。

### 当前 4 步

1. 点两个相同材料  
   玩家点击两片菜叶，合成小青菜。

2. 取材进棋盘  
   玩家点击菜篮，材料进入 4x4 教学棋盘。

3. 确认订单目标  
   教学订单为街坊早餐，需要小青菜和双黄蛋。棋盘对应材料高亮，玩家点击订单卡确认目标。

4. 开始经营  
   告知主屏只放当前操作内容，其余系统在底部入口。

### 已修正问题

- 第三步从“看订单”改为“点击订单卡确认目标”。
- 第三步目标从 3 个材料修正为真实首单的 2 个材料。
- 教程完成后第一单目标和订单入口保持一致。

## 9. 玩法系统拆解

### 9.1 棋盘系统

规格：

- 棋盘 7x9，共 63 格。
- 每个格子为空或持有一个 `BoardItem`。
- `BoardItem` 包含 `uid` 和 `itemId`。

操作：

- 点有物品格子：选中物品。
- 点空格：移动选中物品。
- 点相同物品：二合升级。
- 点不同物品：提示不能合成，切换选中目标。
- 可拖拽移动或合成。

规则：

- 只有相同 `itemId` 且物品定义存在 `next` 时可合成。
- 合成后目标格生成下一等级物品，来源格清空。
- 棋盘满时生成器和制作领取会提示无法放入。

### 9.2 生成器系统

当前生成器：

| 生成器 | 掉落 | 充能 | 冷却 |
| --- | --- | --- | --- |
| 菜篮 | 菜叶、小番茄、鸡蛋、小麦 | 20 | 5 分钟 |
| 花篮 | 花芽、玫瑰苗 | 16 | 5 分钟 |
| 杂货箱 | 纸片、细绳、纸片 | 14 | 6 分钟 |

规则：

- 每次点击消耗 1 体力。
- 掉落随机进入第一个空格。
- 充能归零后进入冷却。
- 冷却完成后恢复半数充能。

### 9.3 物品链

当前基础链：

- 青菜链：菜叶 -> 小青菜 -> 鲜青菜 -> 菜心 -> 精品菜心。
- 番茄链：小番茄 -> 红番茄 -> 甜番茄 -> 番茄篮 -> 精品番茄篮。
- 鸡蛋链：鸡蛋 -> 双黄蛋 -> 蛋篮 -> 鲜蛋盒 -> 精品蛋盒。
- 小麦链：小麦 -> 面粉 -> 面团 -> 发酵面团 -> 精品面团。
- 雏菊链：花芽 -> 小雏菊 -> 雏菊束 -> 雏菊花篮 -> 精品雏菊篮。
- 玫瑰链：玫瑰苗 -> 玫瑰 -> 玫瑰束 -> 玫瑰花盒 -> 精品玫瑰礼盒。
- 包装链：纸片 -> 纸盒 -> 礼盒 -> 精致礼盒 -> 高级礼盒。
- 丝带链：细绳 -> 丝带 -> 蝴蝶结 -> 花结 -> 高级花结。

### 9.4 制作台系统

当前制作台：

- 蒸锅。
- 煎台。
- 礼盒台。

当前配方：

| 配方 | 制作台 | 输入 | 输出 | 时间 |
| --- | --- | --- | --- | --- |
| 青菜包 | 蒸锅 | 面团 + 鲜青菜 | 青菜包 | 90 秒 |
| 番茄煎蛋 | 煎台 | 双黄蛋 + 红番茄 | 番茄煎蛋 | 120 秒 |
| 香草蛋饼 | 煎台 | 蛋篮 + 小雏菊 | 香草蛋饼 | 150 秒 |
| 清晨花礼 | 礼盒台 | 雏菊束 + 纸盒 + 细绳 | 清晨花礼 | 180 秒 |
| 暖心便当 | 礼盒台 | 鲜青菜 + 蛋篮 + 纸盒 | 暖心便当 | 210 秒 |
| 玫瑰甜点盒 | 礼盒台 | 玫瑰束 + 面团 + 礼盒 | 玫瑰甜点盒 | 240 秒 |

规则：

- 每个制作台同时只能制作 1 个配方。
- 开始制作会消耗棋盘材料。
- 到时间后点击制作台领取产物。
- 棋盘无空位时不能领取。

### 9.5 订单系统

订单类型：

- 普通订单：给金币和经验。
- 故事订单：额外给故事点，并弹出顾客故事。

当前订单池共 14 个。初始只显示 2 个，完成后自动补新订单，最多 4 个。

订单提交规则：

- 棋盘上拥有订单所需物品才可提交。
- 提交会消耗对应物品。
- 发放金币、经验、故事点。
- 订单完成后从当前订单中移除。
- 若当前订单少于 4 个，自动补入下一个未完成订单。

### 9.6 今日任务系统

当前任务线：

1. 取一次材料。
2. 合成小青菜。
3. 完成街坊早餐。
4. 开始制作青菜包。
5. 完成热腾腾包子。
6. 修一次门头。

规则：

- 任务状态由里程碑和当前状态推导。
- 玩家可在任务入口选择追踪任务。
- 主棋盘上方只展示追踪任务。
- 所有任务完成后任务列表收起为完成态。

### 9.7 合成图谱

目标：

- 解决“缺材料不知道怎么合成”的问题。

当前行为：

- 优先展示当前目标订单缺少物品。
- 展示每个缺口的已有数量、需求数量和还差数量。
- 展示主要来源生成器或制作台。
- 按当前棋盘已有低阶材料，估算还需要约几次取材。
- 对可合成物品展示基础链路径。
- 对菜品和礼盒展示配方输入。
- 提供“查看全部基础链”和“查看菜品与礼盒配方”折叠内容。

### 9.8 店铺升级系统

店铺区域：

- 门头。
- 餐桌。
- 花架。
- 后厨。

每个区域 3 级。升级消耗金币和故事点，升级后展示小店修复度变化。当前 MVP 以阶段展示为主，不做自由装修摆放。

### 9.9 顾客故事

- 小满。
- 阿诚。
- 沈爷爷。
- 乔小姐。
- 老周。

故事订单完成后弹出故事卡，展示顾客头像、订单标题、剧情文案和奖励。

## 10. 经济与数值

### 钱包

- 金币：订单和出售物品获得，用于店铺升级。
- 体力：点击生成器消耗，模拟广告可补充。
- 经验：订单获得，用于升级。
- 故事点：故事订单获得，用于后续店铺升级。

### 初始数值

- 金币：260。
- 体力：80/80。
- 等级：1。
- 经验：0。
- 故事点：0。

### 经验升级

当前 MVP 简化为：

```text
level = floor(xp / 100) + 1
```

升级时体力回满。

### 当前数值结论

- 初始金币 260，完成第一单后达到 340，足够修一次门头。
- 14 单订单金币合计 3320，加初始金币后累计上限 3580。
- 14 单经验合计 320，对应 Lv.4。
- 14 单故事点合计 8，不足以升满全部 3 级店铺区域。
- 当前首单实际只需要再产出一个鸡蛋，约 4 体力，适合作为首局目标。
- 当前全部订单粗算约 320 体力，适合作为 MVP 内容池，不适合作为完整长期留存内容。

详细订单体力、金币/体力和升级门槛见 `docs/requirements-and-balance.md`。

## 14. 当前已知限制

### 玩法限制

- 没有真实随机种子复现。
- 生成器掉落没有权重，只是等概率。
- 棋盘没有锁格、扩容、背包、撤销。
- 订单池自动补单逻辑简单。
- Web MVP 仍使用模拟广告；Cocos 已接通补体力和制作加速奖励门禁，但尚未配置真实微信广告位。
- 店铺升级暂时主要是展示和数值消耗。
- 店铺升级效果文案尚未全部绑定真实玩法解锁。

### 内容限制

- 物品链和订单数量能支撑 MVP，但还不足以支撑长期留存。
- 顾客故事是单句弹窗，演出较弱。
- 今日任务没有可领取奖励，只作为引导。

### 技术限制

- 原生 DOM 渲染适合验证，不是最终小游戏工程。
- localStorage 只能本机存档。
- CSS 和 UI 字符串后续需要组件化。
- 没有自动化测试脚本纳入 npm 命令。

## 16. MVP 成功标准

### 体验标准

- 新玩家 1 分钟内知道第一步该点哪里。
- 玩家能在 5 分钟内完成至少 1 个订单。
- 玩家能理解缺材料要去图谱查看。
- 玩家不会在首屏因为信息过多而迷路。

### 技术标准

- `npm run build` 通过。
- 关键手机视口无横向溢出。
- 主界面不依赖整页滚动。
- 取材、棋盘、底部导航不互相遮挡。
- 存档刷新后可恢复。

### 内容标准

- 教程目标和真实订单一致。
- 首日任务覆盖取材、合成、订单、制作、装修。
- 每个故事订单有顾客反馈。
- 店铺修复能提供长期目标。
