# 《巷口花食铺》需求闭环与数值平衡稿

版本：MVP Web 原型 v4  
更新时间：2026-07-07  
适用范围：需求打磨、内容排期、数值校准、后续微信小游戏迁移前评审

## 1. 本稿目标

这份文档解决三个问题：

1. 从玩家体验出发，确认每个核心需求是否有入口、有反馈、有后续目标。
2. 从系统设计出发，确认教程、棋盘、订单、图谱、任务、店铺和故事是否形成闭环。
3. 从数值出发，确认首日体力、订单收益、制作时间、升级消耗是否能支撑 MVP。

权威产品说明见 `docs/product-document.md`。本稿是产品文档的落地校准层，后续所有新增需求都应先落到这里，再拆实现任务。

## 2. 产品体验闭环

### 2.1 核心承诺

玩家进入游戏后，应在 1 分钟内理解：

- 我要经营一间老街小店。
- 我可以点生成器取材料。
- 两个相同材料可以合成更高级材料。
- 订单告诉我现在要做什么。
- 缺材料时可以看图谱。
- 完成订单后能修店、看故事、继续开张。

### 2.2 当前闭环路径

```text
新手教学
-> 正式棋盘
-> 追踪任务提示第一步
-> 取材和合成
-> 订单入口确认需求
-> 图谱入口解释缺口
-> 提交订单获得金币/经验/故事点
-> 店铺入口消耗资源升级
-> 顾客故事强化情绪目标
-> 下一批订单继续驱动
```

### 2.3 需求闭环检查表

| 玩家问题 | 当前系统回答 | 当前状态 | 后续要求 |
| --- | --- | --- | --- |
| 我是谁，在做什么？ | 教程和主界面文案说明老街小店重新开张 | 已具备 | 增加开场 3 秒小演出 |
| 第一步点哪里？ | 4 步可操作新手教程 + 追踪任务 | 已具备 | 教程结束后突出第一单入口 |
| 材料从哪里来？ | 3 个生成器 + 图谱来源提示 | 已具备 | 图谱支持点击材料定位来源 |
| 为什么要合成？ | 订单需求和配方需要高阶材料 | 已具备 | 高阶合成增加更明显反馈 |
| 缺什么材料？ | 订单卡和图谱展示缺口、来源、合成链和预计取材次数 | 已具备 | 缺口提示按“最近可达”排序 |
| 做好的东西有什么用？ | 提交订单、制作菜品、出售 | 已具备 | 出售需要二次确认或撤销 |
| 完成订单后干什么？ | 自动补单、任务推进、店铺升级 | 已具备 | 订单完成后增加短动效 |
| 为什么修店？ | 店铺区域展示阶段、修复度和故事目标 | 已具备 | 若后续改为真解锁，再补玩法门槛 |
| 为什么回来？ | 今日任务、订单池、体力恢复 | 部分具备 | 增加每日登录和限时订单 |
| 怎么变强？ | 等级、金币、故事点、店铺区域 | 部分具备 | 等级奖励和区域效果需数值化 |

## 3. 首日体验路径

### 3.1 目标节奏

MVP 首日不是追求长留存，而是验证玩家能否顺着目标玩下去。

| 阶段 | 时长目标 | 玩家行为 | 产品目标 |
| --- | --- | --- | --- |
| 新手教学 | 0-1 分钟 | 合成、取材、确认订单 | 玩家理解核心手势 |
| 第一单 | 1-3 分钟 | 补一个鸡蛋、合成双黄蛋、提交街坊早餐 | 玩家完成第一次订单反馈 |
| 订单扩展 | 3-8 分钟 | 完成清爽菜篮、放学点心等低阶订单 | 玩家理解多链材料 |
| 制作引入 | 8-15 分钟 | 制作青菜包，完成热腾腾包子 | 玩家理解制作台和故事点 |
| 店铺目标 | 15 分钟后 | 修门头或继续订单 | 玩家看到长期成长目标 |

### 3.2 首日任务线

当前任务线为：

1. 取一次材料。
2. 合成小青菜。
3. 完成街坊早餐。
4. 开始制作青菜包。
5. 完成热腾腾包子。
6. 修一次门头。

设计判断：

- 任务是“引导追踪”，不是独立领取奖励。
- 任务行展示的奖励文字应理解为该行为自然带来的系统收益。
- 若后续改成可领取任务奖励，必须增加 `claimedTaskIds`，避免玩家重复领取或误解。

## 4. 系统一致性要求

### 4.1 单一事实源

订单需求、物品链、配方、生成器、升级成本必须以 `src/game/catalog.ts` 为事实源。UI 只能读取定义和状态，不应硬编码物品或奖励。

当前仍允许少量教程文案硬编码，但每次修改首单或初始订单时，必须同步检查：

- `src/game/catalog.ts` 的 `order_001`。
- `src/game/state.ts` 的初始订单和教学棋盘。
- `src/ui/render.ts` 的教程第三步文案和高亮材料。
- `docs/product-document.md` 的首局配置。

### 4.2 店铺升级口径

当前 MVP 已选择“纯表现修复度”路线：店铺升级只承担目标感、资源消耗、店铺外观阶段和故事氛围，不承诺生成器、制作台、配方、订单奖励或订单出现率发生真实变化。

这样做的原因：

- 不打断首局体验，玩家从一开始就能验证完整玩法。
- 避免“文案说解锁，但代码未加锁”的需求不一致。
- 让当前资源消耗可以服务长期目标，而不是阻塞基础功能。

后续若要改为真实解锁，需要同时补齐：

1. 生成器、制作台、配方和订单的解锁条件。
2. 未解锁状态的 UI 展示。
3. 订单池刷新规则。
4. 新手教程和首日任务线。
5. 数值检查脚本里的解锁阶段校验。

### 4.3 图谱责任边界

图谱只解决“这个东西怎么来”，不承担订单排序和资源规划。

最低要求：

- 订单缺口优先展示。
- 展示已有数量、需求数量和还差数量。
- 展示主要来源生成器或制作台。
- 按当前棋盘已有低阶材料估算还需要约几次取材。
- 可合成材料展示完整链路。
- 成品展示制作台和输入材料。
- 基础链和配方可折叠查看。

下一阶段要求：

- 点击缺口材料时，图谱自动定位该材料。
- 缺口列表按“最少预计取材次数”或“当前追踪任务”排序。
- 高级材料估算要继续处理多订单共享库存和制作台排队。

## 5. 数值模型

### 5.1 当前基础假设

体力规则：

- 点击生成器消耗 1 体力。
- 体力上限 80。
- 自然恢复 1 点 / 3 分钟。
- 模拟广告补 30 体力。

合成成本：

- Lv.1 来自生成器。
- Lv.2 需要 2 个 Lv.1。
- Lv.3 需要 4 个 Lv.1。
- Lv.4 需要 8 个 Lv.1。
- Lv.5 需要 16 个 Lv.1。

生成器掉落概率：

| 生成器 | 掉落池 | 单项概率 |
| --- | --- | --- |
| 菜篮 | 菜叶、小番茄、鸡蛋、小麦 | 各 25% |
| 花篮 | 花芽、玫瑰苗 | 各 50% |
| 杂货箱 | 纸片、细绳、纸片 | 纸片 66.7%，细绳 33.3% |

### 5.3 首局实际判断

初始棋盘已经提供：

- 两片菜叶，可直接合成小青菜。
- 一个鸡蛋，只需再产出一个鸡蛋即可合成双黄蛋。

因此第一单“街坊早餐”实际不是 16 体力目标，而是约 4 体力目标。它适合承担首单教学。

### 5.4 经济门槛

店铺升到 2 级的总成本：

| 区域 | 升 2 级金币 | 升 2 级故事点 |
| --- | ---: | ---: |
| 门头 | 300 | 0 |
| 餐桌 | 280 | 0 |
| 花架 | 360 | 1 |
| 后厨 | 420 | 1 |

判断：

- 完成街坊早餐后，金币从 260 到 340，足够修门头。
- 完成热腾腾包子后，故事点达到 1，足够修花架或后厨之一。
- 完成给妈妈的花后，故事点达到 2，理论上可把四个区域都升到 2 级。
- 当前 14 单只给 8 故事点，不足以把四个区域都升到 3 级，这是合理的 MVP 内容边界。

### 5.5 数值目标带

MVP 暂定目标：

| 阶段 | 目标 |
| --- | --- |
| 首单 | 实际期望体力 3-8，无等待 |
| 第一故事单 | 额外体力 25-40，等待不超过 2 分钟 |
| 普通订单 | 金币/体力 4-14 |
| 故事订单 | 金币/体力 7-20，另给故事点 |
| 单次制作 | 90-240 秒，前 15 分钟不超过 3 个制作等待 |
| 首次装修 | 完成 1-3 单可达 |
| 全部 2 级装修 | 完成 8 单左右可达 |
| 全部 3 级装修 | 不在当前 14 单内完成 |

## 6. 当前风险与处理建议

### P0 风险

1. 店铺升级当前是纯表现修复度。  
   处理：进入正式版前若要做真解锁，必须按 4.2 补齐完整门槛，不要只改文案。

2. 任务奖励表达可能被理解为可领取。  
   处理：MVP 文档明确任务是引导；若要奖励，新增领取状态和奖励规则。

3. 生成器随机不可复现。  
   处理：迁移前引入可保存随机种子，方便复盘卡点。

### P1 风险

1. 图谱已有预计取材次数，但还不能点击材料直接定位来源。  
   处理：给缺口材料增加来源和预计体力。

2. 高阶订单对棋盘空间压力没有被量化。  
   处理：自动试玩增加“棋盘接近满格”监控。

3. 订单池是固定顺序补单。  
   处理：后续根据玩家当前库存和店铺等级做轻量推荐。

## 7. 下一步需求拆分

### 必做

1. 继续保持店铺升级文案与“纯表现修复度”一致。
2. 图谱支持点击材料后定位来源和合成链。
3. 为 100 轮自动试玩增加 npm 脚本。
4. 将 `npm run balance` 接入迭代验收门槛。

### 可选

1. 今日任务改为可领取奖励。
2. 订单完成后金币飞行动效。
3. 制作台支持激励广告立即完成。
4. 店铺升级后展示前后对比图。

## 8. 当前结论

当前 MVP 的主循环已经成立：教程能进入第一单，第一单能进入订单池，订单池能引出制作台和故事点，故事点能推动店铺修复。数值上，首单足够轻，首个故事目标可达，14 单不足以毕业全部装修，保留了后续内容空间。

当前最需要打磨的不是再加系统，而是让“目标提示、图谱解释、店铺升级效果、数值收益”彼此说同一套话。
